# Data

```
data/
├─ official_catalog.json            organisers: red-flag points, verdict bands, scam types, official contacts
├─ validation_set/V01..V11.json      organisers: the 11 sample scenarios
├─ validation_expected_results.csv   organisers: their answer key
├─ dataset/                          synthetic training/eval data (generated by the team)
├─ handwritten/                      test scenarios written by people on the team
└─ ood/                              template for new hand-written test sets
```

All organisations, links and phone numbers are fictional, except ANAF.

## Scenario format

One JSON file per scenario, the organisers' format:

```json
{
  "id": "V04",
  "channel": "whatsapp",
  "sender": {"name": null, "address": "+40 7xx xxx 318", "known_contact": false},
  "messages": [
    {"n": 1, "from": "sender", "text": "Bună mami, mi s-a stricat telefonul, ăsta e numărul nou."},
    {"n": 2, "from": "reader", "text": "Cine e?"}
  ]
}
```

`channel` is one of `sms`, `whatsapp`, `email`, `chat`, `call_transcript`. Reader replies count in the
numbering (`n`) but aren't analysed. A single message is a thread of length 1.

Answer keys are CSVs with `id, verdict, scam_type, risk_score, first_alert, red_flags` (flags separated
by `;`, `first_alert` empty for SAFE).

## The synthetic dataset (`dataset/`)

1,700 training and 300 eval conversations, generated from attribute-conditioned templates. Details:
`dataset/README.md` (Romanian), `dataset/STATS.md`, `dataset/LABELING_GUIDE.md`.

- **Per-message labels.** Every message carries its own flags (`train.jsonl`, `eval.jsonl`); the conversation labels follow from the official formula. That is what the flag model trains on.
- **Balance.** 35% SAFE (98.7% of them hard negatives containing trigger words), 15% SUSPICIOUS, 50% SCAM, all 12 scam types, all 5 channels, with and without diacritics.
- **Eval subsets** (`meta.subset`, `meta.hard`): `contrast`, `truncation`, `hard`. See [EVALUATION.md](EVALUATION.md).
- `eval_kit/` holds the 300 eval conversations as individual files in the organisers' format; `checklist.jsonl` holds behavioural tests (invariance, direction).

**Known limitation:** after masking names and amounts, 931 of 1,700 training conversations share a sentence
template with eval. `evaluation/benchmark.py` therefore reports a template-clean eval subset
(`training/data_split.py: eval_clean_ids`).

## Hand-written test sets (`handwritten/`)

| Folder | Scenarios | Notes |
|---|---|---|
| `franci/` | 20 (4 SAFE, 9 SUSPICIOUS, 7 SCAM) | Written by a teammate, labels cleaned and recomputed (`CHANGES.md`) |
| `fix_T1732-T1741/` | 8 | Second batch; the demo set uses these with V01-V11 (`MANUAL_CHANGES.md`, `REPORT.md`) |

Each has `scenarios/*.json`, `expected_results.csv` and `labeled.jsonl` (per-message flags).
`evaluation/clean_human.py` turns a raw hand-written batch into this layout: it fixes formats, checks
links against the catalog, recomputes score, verdict and first alert, and reports what it changed.

## Adding a new blind test set

Use `ood/` (see `ood/README.md`). Write 40-60 scenarios by hand, heavy on genuine messages that look
dangerous; label them with the official codes. Ideally the person who labels isn't the person who
wrote them. Then run `python evaluation\benchmark.py`: it adds an "OOD (team)" line automatically.
Don't change rules or settings after looking at its errors, or it stops being blind.
